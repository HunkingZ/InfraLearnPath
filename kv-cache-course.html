CHAPTER 01 / 表示

词元（Token）、词嵌入（embedding）与 X

定义 → 先认识一行数字

词元（Token）是模型处理文字的基本片段，可以是一个字、一个词的一部分或标点。分词器（tokenizer）把文字切成这些片段，并给每个片段一个整数编号，叫词元编号（token ID）。例如，为了讲解，假设“苹果好吃”被切成“苹果 / 好 / 吃”；真实切分由分词器（tokenizer）决定。

向量（vector）是一串有顺序的数字，例如 [1, 2, 3]；分量（component）是其中一个数字；维度（dimension）是数字个数。词嵌入（embedding）是按词元编号（token ID）查表得到的向量，例如编号 7 查出 [1, 2, 3, 4]。隐藏向量（hidden vector / hidden state）是模型内部用来表示一个词元（Token）的数字向量，最初来自词嵌入（embedding），随后会逐层更新。隐藏维度（hidden size）是这行数字的长度。

矩阵（matrix）是按行列排好的数字表。本文约定：只有一个词元（Token）时，X = [x₁, …, x₄₀₉₆] 是它的整个隐藏向量（hidden vector）；xᵢ 只是一个分量（component）。多个词元（Token）时，X 是每行一个词元（Token）的矩阵（matrix），形状（shape，即各轴的大小）为“词元数 × 隐藏维度（hidden size）”。

直观类比

把词元编号（token ID）当作读者证号，词嵌入（embedding）是查到的初始档案，隐藏向量（hidden vector）是读完上下文后不断更新的档案。一个分量（component）只是档案中的一个数字，不能把它当成整个词的意思。

具体例子 → 指代与一词多义

上下文（context）是解释当前位置时可以参考的周围文字；在本课的因果生成中，是当前位置及之前的可见内容。代词指代（pronoun reference）是“他、她、它”等词所指向的人或事物。例如“她吃了苹果”里的“她”需要联系前文确定是谁。

“小明拿起苹果，他把它吃了。”中，“他”指小明，“它”指苹果。初始词嵌入（embedding）只按编号查表；后面讲的上下文计算才帮助形成这种联系。“我吃了一个苹果”里的苹果是水果，“苹果发布了新电脑”里的苹果是公司。同一个词元编号（token ID）可以有相同初始词嵌入（embedding），但处理上下文后得到不同隐藏向量（hidden vector）。切词不同则连初始编号也可能不同。

一步步计算 → 先小后大

玩具：2 个词元，每个 4 维。
X = [[1,2,3,4], [5,6,7,8]]，形状 2×4，总计 2×4=8 个元素。
投影（projection）是用固定数字表 W 对每行做乘加：
W = [[1,0],[0,1],[1,0],[0,1]]，形状 4×2。
第一行：[1+3, 2+4] = [4,6]。
第二行：[5+7, 6+8] = [12,14]。
因此 XW = [[4,6],[12,14]]。第一行完全没有用第二行的数据。

Llama 3 8B：隐藏维度 4096；3 个词元组成 3×4096 的 X。
元素数 = 3×4096 = 12,288。若 W 为 4096×4096，输出为 3×4096。
每个输出分量是 4096 组乘积的和；每行独立做同一套乘加。

点积（dot product）就是对应分量相乘再求和；矩阵乘法（matrix multiplication）就是把这件事用于每个输出位置。“投影（projection）时各词元（Token）互不干扰”只描述这一步，后面会有跨行的信息交互。

常见误解

X 不是 xᵢ；4096 是一行的宽度，不是句子长度。隐藏向量（hidden vector）的每个分量（component）也没有预先固定成“水果”“人名”这样的可读标签。初始词嵌入（embedding）还没有自动完成代词消歧。

练习题

4 个词元（Token），每个隐藏向量（hidden vector）长 6，X 是什么形状？把第二行改掉，投影（projection）后的第一行会变吗？

查看答案 · 第 1 章
X 的形状（shape）是 4×6，共 24 个元素。固定同一个 W 时第一行不变，因为第一行的乘加只读第一行。上下文交互发生在后续步骤。
我会先把文字看成一串词元，而不是直接把整句话交给模型。每个词元先获得一个编号，再查表得到词嵌入，也就是一行数字。这行数字在模型内部不断更新，叫隐藏向量。以隐藏维度 4096 为例，单个词元的 X 包含 4096 个分量，xᵢ 只是其中一个；多个词元则按行堆成矩阵。接下来做投影，就是每行分别乘同一套权重，因此投影本身不会让不同行交流。比如两行四维向量乘一个四行两列的矩阵，只会得到两行二维结果。苹果在水果句子和公司句子中，可以从同一个初始词嵌入出发，但经过后续上下文计算后具有不同表示。先分清初始表示、上下文表示和矩阵形状，后面的缓存容量才不会算错。
CHAPTER 02 / 深度

层（Layer）：向量宽度不变，理解逐步更新

定义

权重（weight）是训练（training）学到、用来做乘加的数字，例如上一章 W 里的数。层（Layer）在这里指一个变换器块（Transformer block）：一段有自己权重（weight）的处理单元。模型把许多层（Layer）纵向堆叠，上一层的输出送入下一层。每层都有独立权重（weight）。例如 Llama 3 8B 有 32 层（Layer）。

残差连接（residual connection）是把输入直接加到处理结果上，写成 Y = X + F(X)，其中 F 表示这一段处理。相加的两项形状（shape）必须相同。例如 [1,2] + [0.1,0.3] = [1.1,2.3]。所以每个块（Transformer block）的输入和输出保持隐藏维度（hidden size）；中间步骤可以改变宽度，再投影（projection）回来。

直观类比

像多位编辑依次修同一张卡片：每个人有自己的修改规则，卡片仍保留相同栏数。残差连接（residual connection）让编辑“在原稿上加修改”，不必每次从零重写。

具体例子

“小明拿起苹果，他把它吃了。”可以在逐层处理时逐渐加强“他→小明”“它→苹果”的联系。“苹果很好吃”与“苹果发布电脑”的区别会通过不同上下文反映到各层的隐藏向量（hidden vector）。这只是直观说明，并不保证某一特定层（Layer）专门负责代词或水果。

一步步计算

玩具：X=[1,2,3,4]。第一层给出 F₁(X)=[0,1,0,1]。
Y₁=X+F₁(X)=[1,3,3,5]，仍为 4 维。
第二层给出 F₂(Y₁)=[1,0,1,0]。
Y₂=Y₁+F₂(Y₁)=[2,3,4,5]，仍为 4 维。

Llama 3 8B：输入 5×4096 → 第 1 层输出 5×4096 → … → 第 32 层输出 5×4096。
每个边界的元素数 = 5×4096=20,480；32 层不把向量变成 32×4096 维。
仅统计每层一次这样的相加：32×20,480=655,360 次标量加法。
真实块内通常有不止一次残差相加，这不是整模型运算量。

常见误解

层数（number of layers）是深度，隐藏维度（hidden size）是宽度；不能互换。独立权重（independent weights）不等于每个词元（Token）都有一份新权重，同一层的所有词元（Token）共用这一层的权重。残差连接（residual connection）要求相加时对齐，但不要求中间每一步都保持宽度。

练习题

一层输入为 3×4096，内部临时变成 3×1024。可以直接和原输入做残差相加吗？

查看答案 · 第 2 章
不可以。必须先把内部结果投影（projection）回 3×4096，才能逐分量相加。输出仍是 3×4096。
层指的是纵向堆叠的处理块，不是向量中的一个数字。一个词元带着固定宽度的隐藏向量，依次经过不同层，每一层用自己训练得到的权重更新表示。以 Llama 3 8B 为例，32 层的边界都保持 4096 维，因此深度增加不会把单个词元变成十几万维。残差连接是输入加上本层算出的修正量，两边形状必须一致，所以内部即使改变宽度，也要投影回来再相加。直观上像多个编辑依次修改同一张卡片：每个人有不同规则，但卡片栏数不变。对代词指代和苹果的不同含义，上下文表示可以逐层演化；不过不能把每一层硬性命名为某种语言功能。这个区分会直接影响后面按层累加存储的计算。
CHAPTER 03 / 宽度分工

注意力头（attention head）：几路查询，几份记忆

定义

注意力（attention）是让当前位置根据相关程度，从已有位置收集信息的计算。注意力头（attention head）是一路独立的注意力计算，例如一条路线更关注“谁”，另一条更关注“哪个物品”；真实头的功能并不固定为这些语义。

Q 头（Query head）提供当前查询；KV 头（Key-Value head）提供供查询匹配和读取的数据。这里先把两者理解成“提问路线”和“资料路线”，下一章定义具体数字。每头维度（head_dim）是每条路线中向量的长度。对本课使用的 Llama 形状，隐藏维度（hidden size）÷ Q 头数（number of Query heads）= 每头维度（head_dim）。

多头注意力（Multi-Head Attention，MHA）是每个 Q 头（Query head）各用一份 KV 头（Key-Value head）；分组查询注意力（Grouped-Query Attention，GQA）是几个 Q 头（Query head）共用一份 KV 头（Key-Value head）；多查询注意力（Multi-Query Attention，MQA）是所有 Q 头（Query head）共用一份 KV 头（Key-Value head）。这些是架构选择，不是随意改一个数字就能无损切换的运行开关。

直观类比

32 位提问者可以各拿一本资料，也可以每 4 人共用一本，或 32 人共用一本。提问者数量和资料份数不是一回事。

具体例子

“小明拿苹果，他吃了它。”中，不同查询路线可以帮助关联“他”和“小明”、“它”和“苹果”。在“吃苹果”与“苹果发布电脑”中，资料来自不同上下文；共用资料路线不会让水果与公司自动混为一谈，因为匹配数字仍由上下文和学到的权重（weight）决定。

一步步计算

玩具：隐藏维度 8，Q 头 4 → 每头维度=8÷4=2。
若 KV 头 2，则每 2 个 Q 头共用一份 KV；KV 总宽度=2×2=4。
Q 的总宽度=4×2=8，两者不必相等。

Llama 3 8B：4096÷32=128；Q 总宽度=32×128=4096。
实际 GQA：KV 头 8 → 每 4 个 Q 头共用一份 KV；KV 总宽度=8×128=1024。
同宽度对比假设：MHA 用 32 个 KV 头，KV 宽度=4096；MQA 用 1 个 KV 头，KV 宽度=128。

常见误解

头（head）不是层（Layer）：前者是同层里的多条路线，后者是纵向深度。每头维度（head_dim）不是用隐藏维度（hidden size）除以 KV 头数（number of Key-Value heads）。隐藏维度÷Q 头数的关系适用于本课模型，不应当作所有未来架构的通用定律。

练习题

隐藏维度（hidden size）8192，Q 头（Query head）64 个，KV 头（Key-Value head）8 个：每头维度和共享组大小分别是多少？

查看答案 · 第 3 章
每头维度（head_dim）=8192÷64=128；每个 KV 头（Key-Value head）服务 64÷8=8 个 Q 头（Query head）；KV 总宽度=8×128=1024。这也是 Llama 3 70B 使用的头部形状。
注意力头是同一层中的多路注意力计算。我会把查询路线和保存资料的路线分开计数：前者是 Q 头，后者是 KV 头。对 Llama 3 8B，隐藏维度是 4096，32 个 Q 头使每头维度等于 128；但它只有 8 个 KV 头，因此每 4 个查询头共用一份键值资料，KV 总宽度是 1024。MHA 是一对一，GQA 是分组共享，MQA 是全部共享。这个设计减少资料份数，但不是简单减少查询头数，也不是把模型层数减少了。头内部的投影仍然读整个输入隐藏向量，并非天然只看输入向量的一小段。后面计算缓存时应使用 8 个 KV 头，而不是 32 个 Q 头，否则就会把这类模型的缓存高估四倍。
CHAPTER 04 / 注意力的数据流

查询（Query）、键（Key）和值（Value）

定义

查询（Query，Q）是当前位置用来寻找信息的向量；键（Key，K）是被搜索位置用于匹配的向量；值（Value，V）是被匹配后实际取出的内容向量。例如，“它”位置的 Q 寻找“苹果”位置的 K，最后读取它的 V。这些只是功能类比，向量不是可直接读的中文问题或标签。

查询投影权重（Query projection weights，Wq）、键投影权重（Key projection weights，Wk）和值投影权重（Value projection weights，Wv）是三组学到的矩阵（matrix）。公式为 Q=XWq、K=XWk、V=XWv。每层（Layer）各有一套；训练（training）后在常规推理（inference）中冻结（frozen，即不再更新权重）。输入 X 每次仍会变。

旋转位置编码（Rotary Position Embedding，RoPE）是按词元位置旋转向量中成对分量的方法，让查询与键的匹配携带相对位置信息。例如相隔一格与相隔十格会得到不同旋转关系。Llama 中 Q、K 做 RoPE，V 不做。输出投影（output projection，Wo）是把各头结果拼接后映射回隐藏维度（hidden size）的权重矩阵。

加权和（weighted sum）是给各项分别乘一个系数再相加。例如两件物品的内容向量分别为 [2,0]、[0,4]，权重为 0.25、0.75，则结果为 [0.5,3]。这里的权重（attention weights）是本次匹配生成的系数，区别于训练保存的模型权重（model weights）。

直观类比

Q 像检索问题，K 像目录标签，V 像书页内容。先按标签找相关书页，再按相关程度混合内容；Wo 像把各位检索员的结果汇编成一份同宽报告。

具体例子

在“王芳把苹果给李雷，她说它很甜”中，“她”的 Q 可能更匹配“王芳”的 K，“它”的 Q 可能更匹配“苹果”的 K。“苹果发布了电脑，它很轻”中的“它”也可能指电脑；模型必须依赖句子，不能写死词元对。“苹果”的水果与公司含义，会影响各层 X，因而改变 Q、K、V。

一步步计算

玩具单头：X=[1,2]；Wq=[[1,0],[0,1]]；Wk=[[1,1],[0,1]]；Wv=[[2,0],[0,3]]。
Q=[1,2]；K=[1,3]；V=[2,6]。
假设已有两个位置 K₁=[1,0]、K₂=[0,1]，对应 V₁=[2,0]、V₂=[0,4]。
当前 Q=[1,2]，点积分别为 1、2；再除以 √2，得到 0.707、1.414。
平方根（square root）√2 是平方后等于 2 的正数，约 1.414；除以它用于缩放打分。
如何把分数变权重将在下一章计算；若所得权重是 0.33、0.67，输出就是
0.33×[2,0]+0.67×[0,4]=[0.66,2.68]。
RoPE 的小例子：把 [1,0] 旋转 90° 得 [0,1]；真实角度依位置和频率确定。

Llama 3 8B 每层：X 为 T×4096（T 是词元数）。
Wq：4096×4096 → Q 为 T×4096 → 32 路各 T×128。
Wk、Wv：各 4096×1024 → K、V 各 T×1024 → 8 路各 T×128。
每个 Q 头最终产生 128 维结果，32×128=4096 维，拼接后乘 4096×4096 的 Wo。
32 层各自拥有这些矩阵；不是全模型共用一套。

因果遮罩（causal mask）是禁止当前位置看到未来位置的规则，例如第 3 个词元（Token）只能读第 1、2、3 个位置。它保证预测后续文字时不提前偷看答案。后面缓存不变性的推导就依赖这条规则。

常见误解

Wq/Wk/Wv 是权重（weight），Q/K/V 是随输入生成的数据，两者不同。每个头的投影（projection）可读取整行 X，不是简单裁出 128 个原始分量。多个头通过各自 Q、K、V 做跨位置匹配；只有投影步骤逐行独立。Wo 也会混合多头结果。

练习题

两个头各输出 [1,2] 和 [3,4]，拼接后是什么？若 Wo 为 4×6，最终宽度是多少？为什么 V 不需要照搬 Q 的位置旋转？

查看答案 · 第 4 章
拼接是 [1,2,3,4]，形状为 1×4，乘 4×6 后成为 1×6。Llama 的 RoPE 把位置关系放进 Q 与 K 的匹配中，V 保留用来加权汇总的内容表示；这是该架构的设计，不是所有位置编码方案的共同要求。
Q、K、V 都由当前层的隐藏向量分别乘三套投影权重得到。权重训练后冻结，但每次输入产生的 Q、K、V 不同。直观上，Q 是当前问题，K 是用来找信息的标签，V 是真正读取的内容。计算时，当前 Q 与可见位置的 K 做点积并缩放，再把分数转成权重，用这些权重对 V 求加权和。Llama 会在匹配前给 Q、K 加 RoPE 来体现位置，V 不做同样旋转。多个头的输出先拼起来，再经过 Wo 回到隐藏宽度，才能进入残差连接。对 8B 的 GQA，Q 投影输出 4096 维，K 和 V 各只有 1024 维。最后，因果遮罩限制只能读当前及以前位置；这个限制是旧数据可以缓存复用的关键前提。
CHAPTER 05 / 归一化与训练背景

未归一化打分（logits）、软最大函数（softmax）与 z 损失（z-loss）

定义

概率（probability）是表示事件发生可能性的 0 到 1 之间的数，例如 0.75 等于 75%。概率分布（probability distribution）把所有候选的概率列出来，总和为 1；例如两种结果的 [0.25,0.75]。归一化（normalization）是在这里把非负数按总和缩放到和为 1，例如 [1,3] 都除以 4 得 [0.25,0.75]。

未归一化打分（logits）是还没变成概率的一组实数，例如 [1,2]，可以为负也不要求加起来等于 1。软最大函数（softmax）把每个打分做指数运算后，除以所有指数的和，得到总和为 1 的概率。指数函数（exponential function，exp）把数字 z 变成 e 的 z 次方，e≈2.718；例如 exp(0)=1、exp(1)≈2.718。

词表（vocabulary）是所有可输出词元（Token）的编号集合。最终隐藏向量（hidden vector）经过词表输出投影（vocabulary output projection）得到每个候选词元的打分。它和注意力（attention）里对历史位置打分是不同位置的计算，但都能用软最大函数（softmax）归一化。

损失（loss）是训练（training）用来衡量预测差错的数。交叉熵损失（cross-entropy loss）在正确答案为 y 时等于 −ln(pᵧ)。自然对数（natural logarithm，ln）是 exp 的逆运算，如 ln(e)=1。正确答案概率越高，损失越小。推理（inference）时通常按概率采样（sampling，即随机抽取）或取最高分，产生下一个词元（Token）。

对数指数和（logsumexp，LSE）是 ln(Σ exp(zᵢ))；z 损失（z-loss）是给训练目标增加 α×LSE² 的小惩罚项，α 是一个很小的系数（coefficient）。它约束共同的打分偏移，减轻数值漂移；不是所有语言模型都使用。此处讨论语言模型输出打分上的版本；后面专家路由也可能用相关损失，不能混为一谈。[来源 2]

直观类比

打分像选手原始成绩，softmax 像把成绩转成一袋抽签券的份额。所有人成绩同时加 100，券的份额不变；z-loss 则提醒“成绩整体别漂得太远”。

具体例子

在“她把苹果拿起来，它……”中，输出词表可以对“很甜”“开机”等后续片段打分。“我吃苹果”与“苹果发布电脑”会有不同打分。对于“她”和“它”寻找先行词，注意力位置打分也能经过 softmax 形成读取权重，但它不是最终输出词表概率。

一步步计算

玩具 logits=[0,ln 3]≈[0,1.098612]。
① exp 后：[1,3]；② 总和=4；③ 概率=[1/4,3/4]=[0.25,0.75]。
④ 正确答案是第二项：交叉熵=−ln(0.75)=0.287682。
⑤ LSE=ln 4=1.386294；若 α=0.001，z-loss=0.001×1.386294²=0.001922。
总训练损失=0.287682+0.001922=0.289604。
若两项都加 10：概率不变，LSE 变为 11.386294，z-loss≈0.129648。

稳定算法：m=max(z)，pᵢ=exp(zᵢ−m)/Σexp(zⱼ−m)。
LSE=m+ln(Σexp(zⱼ−m))；注意计算 z-loss 时必须把 m 加回来。

常见误解

softmax 不等于“最大值变成 1”；最高概率也不保证正确。数值稳定（numerical stability）的“减最大值”是计算技巧，z-loss 是训练正则项（regularization，即额外约束），两者不同。z-loss 不会把每个打分都直接压成 0，也不是缓存的功能。

CHAPTER 06 / 时间上的复用

键值缓存（KV Cache）：算过的旧资料，接着用

定义

键值缓存（Key-Value Cache，KV Cache）是为每层（Layer）保存历史词元（Token）的 K、V，供后续生成复用的存储。自回归生成（autoregressive generation）指一次生成后续的一个词元（Token），把它接到已有内容之后，再继续预测。由于因果遮罩（causal mask），旧位置永远看不到新追加的未来位置；在权重、位置规则和已有前缀固定时，旧 K、V 不变。

提示词（prompt）是请求提供的已有文字。预填充（Prefill）是把提示词（prompt）的全部位置在每层中并行处理，建立缓存并获得首个输出的预测。层（Layer）之间仍然顺序执行。逐步解码（Decode）是之后每步只对新输入位置计算 Q、K、V，把新 K、V 追加到缓存，Q 与全部可见 K 匹配并读取 V。

请求（request）是一次服务调用，例如提交一段提示词（prompt）并要求生成文字。请求结束后释放独占缓存；若开启共享复用机制，公共部分可保留，具体留到第九章。旧 Q 不会参与下一位置的查询，所以普通推理缓存只存 K、V，不存历史 Q。

直观类比

读小说时把每页的“索引与摘要”存入笔记，下一页用新问题查旧笔记。上一次问过的问题本身，不是下一次检索需要保存的资料。

具体例子

给定“小明拿苹果，他把它”，接下来可能输出“吃”。读“它”时查询前面的苹果；下一步用“吃”的新 Q 读取历史，旧“它”的 Q 不再使用。“苹果好吃”与“苹果发布电脑”的缓存不同，不能只因为出现同一个词就互换。

玩具：提示词 3 个位置，生成第 1 个输出后还继续生成 2 个。
无缓存：处理 3+4+5=12 个位置的投影。
有缓存：先处理 3 个，再处理新增的 1 个、1 个，共 3+1+1=5 个位置。
旧 K、V 被复用，但每步注意力仍要读旧 K、V，不是零成本。

单层每个位置 K、V 共 2×8×128=2048 个元素。
初始单层缓存=4096×2048=8,388,608 个元素；追加两次后=4098×2048=8,392,704 个。

常见误解

缓存（cache）消除的是历史投影等重复计算，并没有消除读取历史的注意力计算。Prefill 不是让未来词元泄漏到过去：并行计算仍遵循遮罩。更改早期提示词、模型权重或位置规则，旧缓存就可能失效。最后一个刚采样出的词元通常要到下一次前向计算（forward pass，即运行模型一步）才会写入自己的 KV；预算按完整保留长度计算更安全。

查看答案 · 第 6 章
无缓存为 5+6+7+8=26 个位置，有缓存为 5+1+1+1=8 个位置。不能省去所有历史读取，新查询仍要通过历史键匹配并汇总历史值。此题计数指投影位置数，不是总计算量或延迟倍数。
KV Cache 的前提是因果自回归生成：新词元追加到后面，不会改变旧位置已经看到的前缀，所以旧位置每层的 K、V 可以复用。服务先做 Prefill，在每一层并行处理提示词中的位置并建立缓存，最后位置可直接用于预测第一个输出。进入 Decode 后，每一步只对新输入位置计算 Q、K、V，新 K、V 追加到缓存，新 Q 查询全部可见历史。旧 Q 只服务旧位置的输出，不会被未来查询使用，因此通常不缓存。比如五个提示位置加三次解码，投影位置数可以从二十六降到八，但历史 K、V 仍然需要读取，所以长上下文并不是免费。请求结束释放独占缓存，能否保留公共前缀则由服务端复用策略决定。
CHAPTER 07 / 从元素数到字节数

键值缓存（KV Cache）容量：六个乘数和一个 2

定义

字节（byte，B）是存储容量单位，1 字节等于 8 个比特（bit，即一个 0 或 1）。每元素字节数（bytes per element）是存一个数需要多少字节。脑浮点 16（Brain Floating Point 16，bf16）是每个数用 16 比特存储的数字格式，所以一个元素用 16÷8=2 字节。例如 10 个 bf16 数用 20 字节。序列长度（sequence length，T）是当前保留的词元（Token）个数；包含已经处理的提示词和输出。批次（batch，B）是一起执行的请求集合，批量大小（batch size）是其中请求数；同长度时，总缓存等于单请求缓存乘批量大小。

图形处理器（Graphics Processing Unit，GPU）是擅长并行乘加的处理器；显存（GPU memory）是它存放权重和运行数据的存储。缓存池（KV pool）是显存中留给键值缓存（KV Cache）的部分。例如 80 GB 总显存里扣掉权重和运行余量，剩余部分才可放缓存。并发（concurrency）是同时保留并处理多少请求，不等于每秒完成多少请求。

直观类比

算仓库箱数：每个词元（Token），每层（Layer），每个 KV 头（Key-Value head）都放两箱，K 一箱、V 一箱；每箱有每头维度（head_dim）那么多数。先数东西，再按每件多大换算容量。

具体例子

“她买了苹果，它很甜”与“苹果发新电脑，它很轻”产生不同数据，但若长度、层数、KV 头数和格式相同，缓存容量相同。语义影响内容，不直接改变相同形状（shape）的元素数。

本课统一口径：字节永远是精确值
十进制：1 KB=1000 B，1 MB=10⁶ B，1 GB=10⁹ B，1 TB=10¹² B。二进制：1 KiB=1024 B，1 MiB=1024² B，1 GiB=1024³ B。课堂常说的“128 KB、512 MB、2 GB”实际常指 128 KiB、512 MiB、2 GiB。本课会保留这些熟悉说法并紧邻标出严格单位；计算器同时显示两种单位。8k/32k/128k 分别取 8192/32768/131072 个词元（Token）。

CHAPTER 08 / 算得动与搬得快

预填充（Prefill）、逐步解码（Decode）与延迟

定义

首词元延迟（Time To First Token，TTFT）是从请求发出到收到首个输出词元的时间，例如 300 毫秒。每输出词元延迟（Time Per Output Token，TPOT）是首个输出之后，相邻输出的平均间隔，常按（最后输出时间−首个输出时间）÷（输出数−1）计算；少于两个输出时不能这样定义。吞吐（throughput）是单位时间完成的工作，例如每秒生成多少词元。带宽（bandwidth）是每秒能搬运多少字节；聚合带宽（aggregate bandwidth）是参与设备带宽之和，但只有数据均匀分片且同时工作时才可能接近。

算力密集（compute-bound）表示主要受乘加速度限制；访存密集（memory-bound）表示主要受搬运数据速度限制。Prefill 通常能让同一份权重服务很多位置的矩阵乘法（matrix multiplication），更接近算力密集；小批量 Decode 每步只产生每个请求一个新位置，常更接近访存密集。大批量或超长上下文会改变瓶颈，不能把这两句话当绝对定律。

高带宽内存（High Bandwidth Memory，HBM）是 GPU 上容量有限但带宽很高的显存；浮点运算（Floating Point Operation，FLOP）是一次浮点算术操作；TFLOPS 表示每秒万亿次这样的操作。八位浮点（8-bit floating point，fp8）是一个数用 8 比特、即 1 字节的格式。稠密计算（dense computation）按完整数据计算，不假定大量零值可跳过；稀疏（sparse）指标可能利用零值而给出更高峰值，不能与稠密峰值混用。

直观类比

Prefill 像整班学生一起读教材，一次拿到书可以反复用；Decode 像每次只回答一道题，却要不断翻书。TTFT 是等第一道答案多久，TPOT 是后续答案之间等多久。

具体例子

“小明拿苹果，他说它很甜”作为提示词时，Prefill 一次处理已有位置；随后逐步输出新词。“苹果发布电脑”即使词元数量相同，概率不同，但读取同形状缓存的理想容量下限一样。代词的语义难度不能替代实际延迟测量。

搬完这些数据，至少需要多久？

所有 GB、TB/s 为十进制。输入的是每步实际需要读取的数据；普通稠密全注意力可用权重和整批 KV 总量估算。聚合峰值仅在均匀分片、同时工作时适用，流水线单流不能直接这样相加。结果为读取时间下限和相应速度上界，非实测保证。

常见误解

带宽模型不能拿“单请求 KV”直接代替“整批 KV”；同一份权重在一个批次中可复用，不应无条件乘 batch。提高 batch 往往提高总吞吐，但不一定提高单流速度。多卡的 HBM 峰值相加不能消除通信或阶段串行。

定义 → 先澄清需求，再算资源

参数（parameter）是模型里可学习的数字，权重（weight）是其主体。稠密模型（Dense model）通常每个词元使用各层完整的主要权重。混合专家模型（Mixture of Experts，MoE）在某些层配置多组子网络，叫专家（expert），由路由器（router）为每个词元选择部分专家。总参数（total parameters）是全部参数数目；激活参数（active parameters）是一次处理某个词元时实际使用的那部分。MoE 可以总参数大、激活参数少，但总权重仍需放在某处。

智能体（agent）是会调用工具、接收结果、再继续推理的程序；系统提示词（system prompt）是它重复遵循的开头规则；工具调用（tool call）是向外部工具请求操作并把返回结果接回对话。分位数（percentile，p50/p95）表示排序后有 50%/95% 的样本不超过该值；最大值（maximum，max）是允许的最高值。服务等级目标（Service Level Objective，SLO）是服务要达到的性能目标，例如 p95 的 TTFT 不超过某个时限。

副本（replica）是一套可以独立服务的完整模型部署，可以跨多张 GPU。每秒请求数（Queries Per Second，QPS）是每秒进入或完成的请求数量，需说明口径。准入控制（admission control）是先检查资源预算，允许一部分请求进入运行，其余排队或拒绝。

并行术语 → 定义与例子先行

张量并行（Tensor Parallelism，TP）是把一层的大矩阵拆到多张 GPU，每层通过集合通信（collective communication，即多卡交换并汇总数据）协作。例如 8 张卡共同完成同一层的乘法。流水线并行（Pipeline Parallelism，PP）是把不同层放到不同 GPU 组，例如前 48 层在节点 A，后 48 层在节点 B。数据并行（Data Parallelism，DP）在推理场景常指部署多个完整副本，分别接不同请求。专家并行（Expert Parallelism，EP）是把 MoE 的不同专家分到不同设备，词元经全到全通信（all-to-all，即向多个目标分别发送数据）送给对应专家。

微批次（microbatch）是把大批次拆成的小份，让 PP 各阶段交错工作。流水线气泡（pipeline bubble）是一些阶段等输入或等其他阶段而空闲的时间。例如两个阶段只有一份工作时，后一阶段要先等前一阶段完成。

本练习拓扑选择：2 个节点×每节点 8 张 H100。
TP=8 放节点内；PP=2 跨节点；TP×PP=16 张卡构成一个副本。
96 层均分：每阶段 48 层；权重约 1000÷2÷8=62.5 GB/卡。
每卡 80×0.9−62.5=9.5 GB 简化 KV 预算；16×9.5=152 GB。
8 个 KV 头恰好可在 TP=8 时分到每卡 1 个，假设实现支持且分配均匀。
若增加 DP=2：2 个副本共需 32 卡，容量与总 QPS 有望提高，单请求不自动加快。

为什么通常不把 TP 跨节点？TP 每层都要同步，网络带宽与延迟容易反复进入每个词元的关键路径；节点内 NVLink 更适合这种高频交换。PP 只在阶段边界传中间隐藏向量（hidden vector），跨节点通信次数少，但有串行与气泡代价。TP 跨节点可以实现，并非逻辑上“不行”；只有拓扑与实测说明收益可接受时才选择。MoE 还需同时考虑 EP 的路由负载和 all-to-all 成本。

空间分配与三项服务优化

最大运行序列数（max_num_seqs）是服务引擎允许同时运行的序列上限。例如按 p95=32k 做基线，bf16 权重场景容量上界是 11，而非把 8k 的 47 当所有请求都安全的上限。max=128k 的长请求还要逐个按实际预算准入，必要时独立队列；p95 不是最大值保护。

分页注意力（PagedAttention）把 KV 按固定大小的块分配，通过块表找到逻辑连续、物理可不连续的数据，减少预先保留整条最大长度造成的浪费；但块尾仍可能有少量空隙。前缀缓存（prefix caching）复用完全相同开头的已算 KV，省重复 Prefill；匹配必须包括相同词元前缀、模型版本和位置等配置。例如 100 个请求共用 2k 规则，一份公共块可通过引用计数（reference counting，即记录还有多少请求在用）共享，结束后归还独占块。[来源 4]

分块预填充（Chunked Prefill）把长提示词拆成多块穿插执行，避免一次大 Prefill 长时间阻塞正在 Decode 的请求；它主要平衡延迟和调度，不能神奇地消除总 KV。预填充/解码分离（Prefill/Decode disaggregation）让两阶段用不同资源池，各自扩缩和优化；代价是跨池搬运 KV、路由和容量管理。其收益必须大于 KV 迁移成本。[来源 4]

CHAPTER 10 / 集群资源治理

GPU 集群（GPU cluster）：训练、推理与强化学习

定义 → 负载与调度

集群（cluster）是多台节点（node）组成的资源集合；负载（workload）是要运行的任务；调度（scheduling）是决定任务何时、在哪些设备上运行。强化学习（Reinforcement Learning，RL）是利用奖励信号改进模型的训练方式。在大语言模型的在线强化学习中，采样生成（rollout）是让当前模型生成候选回答或交互轨迹，再按奖励更新模型，因此会交替出现推理与训练负载。

成组调度（gang scheduling）是为一个分布式任务准备好整组资源后再启动，避免八张卡只拿到七张而互相等待。检查点（checkpoint）是可恢复训练状态的快照，通常包括模型参数、优化器状态（optimizer state，即更新参数所需的辅助数据）和进度。抢占（preemption）是为更高优先级任务收回资源；训练如果能从检查点恢复，较适合被受控抢占。对正在服务的在线推理，抢占会中断请求并破坏 SLO，应重点保障。

直观类比

训练像预约一整队工人的大工程，缺人就无法开工；推理像必须准点发车的公交；RL 像潮汐车流，生成答案时需要一批车，回去更新模型时又转成另一类工作。

具体例子

训练用“王芳拿苹果，她吃了它”和“苹果发布电脑，它很轻”等样本学习语义；推理要即时响应同类提问；RL 则先生成多种含代词的回答、评估奖励，再更新模型。这三种工作可使用相同 GPU，却有不同的中断容忍度和时序。

容器编排（Kubernetes）中的机制：定义 → 小例子

Kubernetes是管理容器化任务与节点资源的系统；容器（container）是封装程序及运行环境的方式；容器组（Pod）是 Kubernetes 的基本调度单元，例如一个推理进程及其辅助程序一起部署。

  • 节点池（node pool）：按硬件或用途分组的节点。例如 H100 在线推理池和训练池，分别管理容量。
  • 污点（taint）/容忍（toleration）：污点阻止不匹配的容器组进入，容忍允许其进入。例如给推理节点加专用污点，只有被授权的容器组容忍它。容忍只是“准许”，不是“保证放上去”；还需节点选择器（node selector）或节点亲和性（node affinity，即约束选择哪些节点）。
  • GPU 设备插件（GPU device plugin）：把 GPU 作为可申请资源公布给 Kubernetes。例如容器组申请 8 个 nvidia.com/gpu。插件本身不解决模型拓扑、KV 或多任务隔离。
  • 资源配额（resource quota）：限制某团队或命名空间（namespace，即资源管理分组）能申请多少资源。例如训练最多用 32 张卡，避免无限挤占。
  • 优先级（priority）：表达任务相对重要程度。例如推理高于可恢复训练。优先级本身不保证自动完成检查点；必须设计通知、宽限期与恢复流程。
  • 成组调度（gang scheduling）：例如 16 卡训练必须同时得到两台 8 卡节点。通常要搭配批处理调度器或队列管理器，不能把普通逐个 Pod 调度当成自动成组。
  • 整节点分配（whole-node allocation）：把一台 8 卡节点整体交给一组任务，减少碎片（fragmentation，即总量够但分散后无法满足任务）的同时保持高速互联。会牺牲部分细粒度利用率。

[来源 5] 这些机制各管一部分；“GPU 可被申请”不等于“具备成组调度和严格 SLO 保障”。

一步步计算

玩具：2 台节点，每台 4 张 GPU。各节点已占用 1 张。
总空闲=2×3=6 张，但要求单节点 4 卡的 TP 作业仍放不下。
“总空闲 6≥4”不能推导出任务可运行。

沿用本练习 16 张 H100/副本：假设有 64 张，即 8 台 8 卡节点。
推理保障池保留 32 张=2 个副本；共享池 32 张=4 个节点。
训练可借共享池 16 张=2 节点；推理突增需加 1 副本时，要收回完整 16 张。
若训练每 10 分钟存检查点，任意时刻抢占最坏可能重做近 10 分钟训练，
还要加保存、退出、加载 1000 GB 权重和预热时间；不能声称瞬时扩容。

折中方案：建立“推理保障池 + 训练共享池”。保障池预留在线最低容量；共享池允许训练借用空闲卡，约定可随时被抢回的资源权利，但实际回收仍有有限延迟。为峰值准备预热副本（warm replica，即权重已载入且初始化完成的备用服务）、预测扩容和训练检查点流程。RL 按阶段从共享队列申请资源，记录阶段切换，避免两个阶段各占资源却互等。

常见误解

训练可被抢占不等于训练不重要；在线推理不能被随意打断不等于永远不能迁移，需要先排空（drain，即停止新请求并等已有请求完成）或有状态迁移。配额不自动消除碎片，容忍不保证调度，设备插件不等于完整 GPU 调度系统。快速扩缩容仍受大权重加载限制。

练习题

4 台 8 卡节点各剩 4 卡，合计空闲 16 卡，是否足够放进需要 TP8×PP2、要求每阶段独占一个 8 卡节点的本练习副本？

查看答案 · 第 10 章
不够。总量虽是 16 卡，却没有两台各完整 8 卡的节点。必须成组收回两台节点或重排可恢复任务。把 4+4 卡跨节点凑成 TP8 会改变既定拓扑，必须重新评估通信和 SLO。
我会先按可中断性和资源形态分池。训练需要成组拿到多卡，通信拓扑稳定，能通过检查点受控恢复；在线推理有硬延迟目标，要有最低保障和预热容量，不能直接被训练挤掉；RL 则把 rollout 和更新分阶段调度，因为两者会交替形成资源脉冲。Kubernetes 上，设备插件暴露 GPU，节点池和污点容忍隔离用途，配额限制团队占用，优先级表达资源收回顺序，成组调度保证分布式任务一起启动。我倾向关键推理用保障池，训练在共享池运行并借用空闲资源，峰值时按约定归还。这个归还不是零延迟，必须预算检查点、退出、权重加载和预热。最后尽量按整节点分配高速并行组，避免看起来空闲很多，却因卡散在多个节点而无法启动。
CHAPTER 11 / 性能诊断

性能调试（performance debugging）：先确定慢在哪里

定义 → 先给指标命名

性能调试（performance debugging）是用可复现输入和测量证据寻找瓶颈，再验证优化是否有效；例如同一长度和并发下比较两次 TPOT，而不是凭感觉加卡。流式多处理器（Streaming Multiprocessor，SM）是 GPU 执行计算的单元；SM 利用率（SM utilization）描述观测区间内这些单元的活跃情况，具体计数器定义依工具而异，不等于有效模型运算比例。

显存带宽利用率（memory bandwidth utilization）是实际搬运字节速率相对参考峰值的比例。模型算力利用率（Model FLOPs Utilization，MFU）是有效模型运算量÷运行时间÷对应硬件稠密峰值，例如实际 100 TFLOPS 对 1000 TFLOPS 为 10%；需要说明运算计数方法、精度和是否包含注意力。KV 池利用率（KV pool utilization）是已占缓存块相对可用块的比例。前缀命中率（prefix hit rate）是复用前缀的比例，必须说明按请求数还是按词元数统计。

排队时间（queueing time）是请求等候准入与执行的时间。抢占次数（preemption count）在这里指推理引擎因缓存压力暂停、换出或重算请求的次数，不同于上一章的 Kubernetes 作业抢占。投机解码（speculative decoding）用较便宜的草稿模型（draft model）或预测机制提出多个候选，再由目标模型（target model）验证，争取一次接受多个输出；例如一次验证三个候选而接受两个。收益取决于接受率和验证成本。

直观类比

餐厅慢可能是门口排队、厨房做首道菜慢，或后续上菜间隔长。先看哪一段耽误时间，再决定加厨师、拓宽传菜通道还是改排单方式。

具体例子

“她拿苹果，它很甜”与“苹果发布电脑，它很轻”如果长度和输出预算匹配，可以组成可复现测试组；代词不同不能让我们跳过长度控制。若真实 agent 加入工具结果，输入可能突然变长，应把这些回合单独统计，避免平均值掩盖 p95。

按这个次序排查

  1. 先分症状：TTFT 慢，拆排队、分词、Prefill、首输出传输；TPOT 慢，查看 Decode 步时和长尾；吞吐低，核实到达负载是否足够以及统计的是词元还是请求。
  2. 再对齐测试条件：记录模型版本、精度、输入/输出长度分布、并发和前缀是否预热。避免拿短输入热缓存对比长输入冷缓存。
  3. 再看指标组合：SM 活跃但带宽低，检查小算子、同步与调度空隙；带宽接近上限而 MFU 低，可能是正常的访存瓶颈；KV 池高、抢占增多、排队变长，先检查长度预算、准入和缓存块回收；前缀命中低，检查实际词元前缀和路由。
  4. 然后看多卡：测 TP 跨节点通信是否占关键路径；看 PP 气泡和阶段负载是否失衡。不能把卡数增加当成通信变快。
  5. 最后做有针对性的优化：容量不足才评估加卡或低精度；带宽不足才评估换卡、增加批量或缩短上下文；低并发的逐步生成可评估投机解码。每次改一项，复测质量、TTFT、TPOT 和成本。

一步步计算

玩具：TTFT=排队 120ms+分词 5ms+Prefill 60ms+发送 15ms=200ms。
若将 Prefill 加速一倍：新 TTFT=120+5+30+15=170ms，仅改善 15%。
不能把纯计算提速 2 倍说成端到端提速 2 倍。

Llama 3 8B 示例：上一章带宽模型每步读取约 20.295 GB。
若实测步时 10ms，推算平均有效读取带宽=20.295÷0.010=2029.5 GB/s。
相对 3350 GB/s 峰值=60.58%；这只是估算，应以硬件计数器校验。
若本练习 16 张 H100 的 bf16 峰值=16×989=15,824 TFLOPS，
测得有效模型计算为 4000 TFLOPS，则 MFU=4000÷15,824≈25.28%。
4000 是教学测量假设，不是 500B 实测结果，也不是 Decode 的必达 MFU。

常见误解

SM 利用率高不等于吞吐好；Decode 的低 MFU 不一定是实现糟糕；缓存占满有时是有益前缀保留，但若持续抢占与排队，就是压力信号。fp8 不保证端到端翻倍；投机解码也不保证高接受率。先验证瓶颈再投入。

练习题

p95 TTFT 很慢，但 Prefill 计算时间稳定，排队从 20ms 涨到 800ms；TPOT 正常。首先做什么？

查看答案 · 第 11 章
先检查到达流量、准入上限、可用副本、KV 预算与长请求占用，确认队列为何积压。扩副本或改变队列策略可能有帮助，但不能把优化注意力算子当首选。复测需看 p95 排队与端到端 TTFT，防止只把等待挪到别处。
我会先分清是首词元慢、后续每词元慢，还是总体吞吐不足，并把端到端时间拆开。TTFT 慢先看队列和 Prefill，TPOT 慢先看 Decode 的内存与通信路径，吞吐低还要确认负载和批次是否喂足。然后同时看 SM、带宽、MFU、KV 池、前缀命中、抢占和排队，避免单指标误判。例如带宽已高而 MFU 低，可能符合访存密集的预期；KV 紧张伴随抢占，则更像容量和准入问题。多卡再看 TP 的跨节点同步，以及 PP 的气泡和阶段失衡。最后才决定加卡、换卡、低精度或投机解码，每项都通过受控对比验证。目标不是让某个利用率数字好看，而是在质量和成本约束下达成延迟与吞吐目标。
CHAPTER 12 / 热数据与冷数据

缓存卸载（KV Cache Offload）与多级缓存（Multi-Tier KV Cache）

定义

缓存卸载（KV Cache Offload）是把部分 KV 从 GPU 显存移到其他存储，在需要时再取回，例如把暂停会话的 KV 放到主机内存。多级缓存（Multi-Tier KV Cache）按访问频率与速度把数据放到不同层级。热数据（hot data）是近期频繁使用的数据，例如正在 Decode 的请求所需 KV；冷数据（cold data）是不常使用的数据，例如长时间暂停的会话。

中央处理器（Central Processing Unit，CPU）是主机的通用处理器；动态随机存取内存（Dynamic Random-Access Memory，DRAM）是主机内存。高速外设互联（Peripheral Component Interconnect Express，PCIe）连接主机与 GPU，卸载数据常需经过它；本课用有效单向 64 GB/s 做演算假设，不把双向合计标称值直接代入。非易失内存快速接口固态盘（NVMe SSD）是通过 NVMe 协议访问的固态存储；远端存储（remote storage）是需经网络访问的存储。

预取（prefetch）是在计算真正需要前先搬数据，例如处理当前层时提前搬下一层 KV；窗口注意力（sliding-window attention）是按模型设计只读取最近一段历史的注意力，例如只读最近 4096 个位置。全注意力（full attention）要访问全部可见历史，不能擅自丢远处 KV 而宣称计算结果等价。

直观类比

HBM 像桌面，CPU DRAM 像房间里的柜子，SSD 像档案室，远端像外地仓库。正在写文章时，把每一步都要翻的整本资料运去外地，桌面空了，但写作会被搬运拖慢。

具体例子

agent 问“她拿起苹果，她把它放在哪里？”后等工具一分钟，暂停会话的 KV 可以换出；工具回来再搬回。“苹果好吃”与“苹果发布电脑”可以共享相同规则前缀，却不能因为都有“苹果”就共享请求专属数据。只有完整相同前缀和兼容配置才能正确复用。

层级（tier）适合放什么取舍（trade-off）
HBM正在 Decode 的热请求；当前计算所需层或块速度快，容量贵且有限
CPU DRAM暂停、换出的请求；跨轮会话；共享前缀的较温层容量大，搬入 GPU 受 PCIe 等链路限制
NVMe SSD较冷会话、归档、持久化前缀库高容量，但加载延迟与带宽更受限
远端存储（remote storage）跨机器共享前缀库、长期归档还需网络传输、目录索引与失效管理

四种用法：每一种都先明确何时搬

  1. 抢占换出（preemption with swapping）：缓存紧张时把暂停请求移到 DRAM，恢复时搬回，避免重做整个 Prefill。是否比重算便宜取决于两次搬运成本和原 Prefill 成本，不能直接照搬某引擎的默认抢占策略。
  2. 按层或窗口分层（layer/window tiering）加预取（prefetch）：HBM 只放当前需要的层或按模型窗口保留热块，提前取下一部分。它可降低驻留容量，但全注意力每步的总历史读取量不会因分层自动减少；预取只有在搬运能被计算掩盖时才有益。窗口改变必须符合模型本身的语义。
  3. 会话与前缀分层（session/prefix tiering）：不活跃会话和公共前缀先留 DRAM、SSD 或远端，需要时一次性恢复到热层。它减少重复 Prefill 和空闲驻留，但复用之后的 Decode 仍须及时获得这些 KV。
  4. 全量卸载（full offload）：让绝大多数 KV 常驻主机并在每步搬入；在本课全注意力和 PCIe 假设下通常只适合离线（offline，即不要求即时响应）、低 QPS、对延迟宽松的任务。不能仅凭“内存够大”保证交互聊天体验。特殊互联或稀疏算法需另算。

一步步计算 → 为什么热 Decode 不能整本搬

玩具：热 KV 共 1 GB，每一步都要读。
本地带宽 100 GB/s → 1÷100=0.01s=10ms。
外部链路 4 GB/s → 1÷4=0.25s=250ms。
分 10 块预取，每块耗时虽小，总字节数仍为 1 GB。

Llama 3 8B 形状外推：128k=131,072 词元，bf16 KV。
每词元 65,536 个元素；总元素=65,536×131,072=8,589,934,592。
乘 2 B=17,179,869,184 B=16 GiB≈17.180 GB。
HBM：17.180÷3350=0.005128s≈5.13ms/步，仅算 KV 读取。
PCIe 假设有效单向 64 GB/s：17.180÷64=0.268435s≈268ms/步。
课堂十进制圆整：把“16 GB”直接代入 → 16÷3350≈4.78ms，16÷64=250ms。
所以常说“HBM 约 5ms，PCIe 约 250ms”，严格单位对应约 5.13ms 与 268ms。
这还没算权重、计算与软件开销，整本逐步搬运会限制交互速度。
这里是按 Llama 3 8B 的 KV 形状做 128k 容量外推。原版 Llama 3 8B 的官方上下文为 8192，并不支持直接据此认定能正确处理 128k。支持长上下文需要对应模型与位置配置；形状估算不能证明模型能力。
再算一次性恢复的取舍：若同一 16 GiB 会话从 DRAM 恢复一次，理想搬回约 268ms。
若随后在 HBM 中连续输出 100 个词元，平均分摊恢复开销≈268÷100=2.68ms/词元。
若每个词元都完整从 DRAM 搬一次，则约 268ms/词元。
若换出后还要搬回，总搬运下限约 2×268=536ms；应与重算 Prefill 的实测时间比较。

常见误解

DRAM 本身的带宽不等于 GPU 读取它的端到端带宽；要看最窄链路与 NUMA 拓扑（Non-Uniform Memory Access topology，即主机不同内存位置的访问代价差异）。共享前缀不意味着生成时再也不读它。预取能重叠时间，不能消灭字节。缓存恢复还要校验模型、词元前缀、位置、数据格式、并行布局和租户权限，错误复用会破坏正确性。

练习题

一个 8 GB 冷会话通过有效 32 GB/s 链路恢复，理想恢复多久？若要求热 Decode 每步≤50ms，可以每步全量搬入这 8 GB 吗？

查看答案 · 第 12 章
8÷32=0.25s=250ms。仅搬运已超过 50ms，因此无法按这个全量逐步搬运方案达标。可把暂停会话放冷层、恢复后驻留 HBM，或者采用经过验证的其他算法或互联；不能把冷层总容量当成热层有效容量。
我会按热度而不是只按容量设计 KV 多级缓存。正在逐步解码的热数据尽量放 HBM，暂停会话与可恢复前缀放主机内存，较冷内容和共享库再放 SSD 或远端。卸载主要有四种用途：抢占换出避免重算，按层或窗口分层并预取，跨轮会话与前缀复用，以及延迟宽松的全量卸载。关键是算数据路径：按 8B 的形状，128k KV 是 16 GiB，H100 HBM 理想读取约五毫秒，而有效 64 GB 每秒的 PCIe 链路约需 268 毫秒；课堂圆整可说约 250 毫秒。若每步都搬，交互速度会很差。冷会话一次性恢复再留在 HBM 则可以分摊开销。预取不能消除总流量，全注意力也不能随意丢远历史；最终要比较搬运、重算与 SLO。
